## 4. Founder product direction, recorded at Baseline V1

The Founder set the following direction at the time of this promotion. It governs how
customer-facing conversation must be built from here forward — **it is a directive for
future milestones, not a change made to this codebase now.** No source file was modified
to implement it as part of this commit; `next` work must honor it from the start rather
than retrofit it.

> **Production and demo customer-facing conversation must not be scripted.**
>
> Normal dialogue must be dynamically generated by the LLM from:
> - the current conversation
> - durable conversation history
> - contact context
> - business/product context
> - qualification state
> - previous conversations
> - tool results
> - the current objective
>
> Canned response trees, predefined question flows, or hardcoded conversational wording
> must **not** be implemented for production/demo conversations.
>
> `ScriptedLlmProvider` / deterministic model doubles remain allowed and desirable **only**
> for automated deterministic tests — the same reasoning `docs/DECISIONS.md` already
> applies to `DeterministicTelephonyProvider` and `DeterministicCalendarProvider`: a test
> needs a reproducible double; a real conversation with a real person does not.
>
> Application code remains responsible for: validation, scheduling, timezone/business-hours
> rules, permissions, persistence, tool execution, and external actions — **unchanged** from
> the governing rule this baseline already ships with (`docs/ARCHITECTURE.md` § 1: *"the LLM
> reasons and converses; application code owns state and executes actions"*). This directive
> narrows what "reasons and converses" is allowed to mean for a real conversation: the model
> must actually do that reasoning and converse dynamically, not select from prewritten text.

**What this means concretely for whoever picks up the next milestone**, so it doesn't have
to be re-derived from the paragraph above:

- `ScriptedLlmProvider` stays exactly where it is (`src/llm/scriptedLlmProvider.ts`) and
  keeps driving every test and the 601-scenario sweep — nothing here asks for that to
  change, and the sweep's determinism guarantee depends on it staying deterministic.
- A production/demo path must drive conversation through `OpenAiLlmProvider` (or an
  equivalent dynamic provider behind the same `LlmProvider` port) — `npm run slice:demo`
  currently defaults to the scripted model for safety with no key configured; that default
  is fine for a credential-less demo, but a real customer conversation must not ship
  wired to it.
- Nothing about the **tool contract**, the **validation chokepoint**, or any of the nine
  tools changes because of this directive. The model still only ever *proposes* — through
  `schedule_followup`, `schedule_meeting`, and the rest — with application code still the
  only thing that validates, persists, or acts. This directive is about how the model's
  own *words* to the contact are produced, not about widening what it's allowed to do.
